# 维护、私人数据与分享

## 两层存储

公共包：SKILL、通用reference、空白模板和检查脚本。私人目录：实际档案、训练记录、病例、照片、原始聊天、个体课表和内容授权；放在用户指定的仓库外位置。

公共包和私人目录不是两个互相竞争的版本。公共包只回答“怎么判断、引用哪些通用证据、如何输出”；私人目录只回答“这个人是谁、最近实际练了什么、有哪些授权数据”。运行时先加载公共 skill，再按用户授权读取私人目录；不要把私人目录反写进公共包。

`.gitignore`不能抹去已跟踪内容或旧提交。不要将包含真实档案的整个Wiki同步到公共包，也不要用批量删除同步命令覆盖用户资料。改写前先确认备份可读取，保留原始私有版本。

新用户只能访问其明确授权的数据。多人服务优先按用户代号隔离，任何单个用户的偏好和病史都不能写成全局规则。

## 分享流程

1. 明确发布的是skill目录、压缩包、分支还是整个仓库。公开文件清洁不等于整个仓库历史清洁。
2. 检查公开文件白名单，空白模板保持空白，检查相对链接可独立解析。拒绝夹带日志、媒体、缓存、个人路径、联系方式和填好的档案。
3. 在仓库根目录运行 `python3 skills/human-upgrade-plan/scripts/check_public.py --root .`。脚本只读，发现问题返回非零；可用 `--deny-term` 临时传入当前用户的识别词，识别词不要写进公共脚本或提交。
4. 人工复核去姓名后仍可能识别个人的赛事、成绩、日期、单位与病史组合。静态检查不能证明匿名。
5. 仅将本次明确公共文件提交，检查暂存内容及待推送历史。若旧历史含私人数据，选择干净独立历史的发布载体，说明旧分支仍保留信息；重写历史、删除分支、改公开性需单独明确授权。
6. 推送后核验分支指向、提交文件清单和历史。复制文件或本地提交不代表上传成功。

## 知识维护

先写通用证据卡再更新导航，按DOI/PMID去重。案例应用留在私人档案；公共库只保留通用训练变量、边界和经授权的示例。更新论文阅读状态应有相应的读取证据。

公开版本可随包携带知识，避免依赖作者电脑绝对路径。旧库题录候选保留为待核验索引，不自动继承“精读”标签。

## 对话恢复与沉淀

从 Cursor、Codex 或其他客户端恢复出的聊天记录只能作为临时来源。沉淀到公共 skill 前必须改写为通用规则、证据卡或维护说明；不要把原始对话、请求ID、截图路径、用户姓名、训练日志或客户端缓存文件直接提交。

若恢复内容涉及文献扩充，先写入 `references/evidence/` 下的主题包或证据卡，再更新 `training-knowledge-system.md` 与 `README.md` 的索引。若只涉及某个用户的下一次训练或个人反馈，写入私人目录，不进入公共包。
