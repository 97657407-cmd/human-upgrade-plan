# 用户建档与目标评估

此文件定义建档方法，不保存真实人员数据。空白模板见 [profile-template](../assets/profile-template.md)。

## 首次对话（两轮即可开训）

### 第一轮：基础问题（一次只问这组）

优先问影响当前方案的少量问题：

1. 目标项目与大致日期（健康能跑 / 完赛 / 提速 / 力量 / 学习）
2. 近几周真实训练（没有就说没有；旧 PB 只作经验）
3. 有无影响运动的症状或医疗限制
4. 每周可用天数、单次时长、场地器械
5. 当前睡眠与工作压力（久坐 / 久站 / 轮班可一句话）
6. **手表或运动设备品牌**（高驰 / 佳明 / 苹果 / 华为 / 颂拓 / 没有 / 其他）——详见 [设备数据](device-data.md)

已有回答直接沿用并标注日期；不要要求一次填完长问卷。

仅收集训练所需信息。昵称或随机代号即可，真实姓名、联系方式、精确地址、单位名称都不是排课必需。年龄/训练年限、身高体重等按目的可选；不愿提供时说明哪些推断受限。涉及医疗情况只记录必要摘要和来源，未经明确需要不保存原始报告。

### 第二轮：跟进具体需求

基础信息够用后，用一句话确认本轮主任务，例如：

- “你现在最想先解决哪一件：本周课表 / 某场比赛 / 伤后怎么恢复练 / 力量怎么加 / 下班太累怎么取舍？”
- 若用户已提出具体需求，直接进入该需求，不再重复盘问。

然后给出可执行建议，并说明为什么、相关原理与文献边界（见 [输出格式](output-patterns.md)）。

## 目标

明确主目标和次目标、赛事期限、愿意投入的时间、训练体验偏好。区分健康活动、入门完赛、竞技提升、增肌力量、教练学习；不把健康指南剂量等同竞技计划。

成绩预测只在近期可信表现、训练连续性和恢复信息足够时给条件范围；缺少证据则先定义评估节点。历史成绩能说明经验，不能决定当前间歇配速。

## 私人数据管理

私人目录由用户指定，且应处于公共skill和任何待发布Git目录之外。使用 [维护与隐私](wiki-maintenance.md)。多用户场景先确认当前代号，禁止混用档案。允许只在当前对话使用，不强制落盘。
